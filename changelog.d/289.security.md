**Release and repository checks: the release builds the commit it verified, OIDC only where it is used, and the guards cover every Dockerfile, pip spelling and approver** — `maestra-release.yml` checked out the tag by name in `verify`, `ci` and `image`, so a tag moved while a run was in progress could have `image` build and sign a commit the ancestry check and CI never saw; every job now checks out `github.sha`. The workflow-wide `id-token: write` is replaced by per-job grants to `image` and `ci` only, and the header and MAESTRA.md no longer claim the `nora-release` environment stops an edited copy of the workflow: its rule matches the tag name, so the release boundary is the tag ruleset (create, update and delete) together with a Teleport token that requires the environment claim. `check-upstream-workflows.sh` now also fails on a release checkout that is not of `github.sha`, on an OIDC grant to any other job, and on a hash-less `pip3`, `pip3.12` or `uv pip` install (it matched only `pip install`). `coherence-check.sh` checks the bases of `deploy/Dockerfile.*` as well as the root `Dockerfile` (release.yml builds `deploy/Dockerfile.release`). The upstream `auto-reland.yml` guard counts only approvals by reviewers with write access when it finds the approved commit. (audit R04, R18, R26, R27, R28)
