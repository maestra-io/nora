**Token hardening: 128-bit secrets, no-store and small bodies on token routes, restore keeps revocations** — a new `nra_` token secret is 128 random bits (it was a UUIDv4, 122 bits) in the same `nra_` + 32 hex shape, so issued tokens keep working. Replies of `/api/tokens*` and `/api/oidc/session` carry `Cache-Control: no-store`, and a `/api/tokens*` body over 16 KiB is answered 413 before the handler reads it (it was capped only by the server-wide upload limit). `nora restore` onto a store that already holds token records keeps that store's token set, so a token revoked since the backup is not brought back; it prints how many archive records it left out, and `--include-tokens` restores them all for disaster recovery (audit A025, B05, B17, B30).
