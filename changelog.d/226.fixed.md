**Docker: a push behind an unserved registry host is refused, and tags/list of a proxied repository asks the upstream (R4-R11, R4-R09, #226)** — a write whose first segment is a registry host no upstream serves (`quay.io/team/app` with no quay upstream) is 400 `NAME_INVALID` instead of being stored as `team/app`, where a pull without the host found it. `tags/list` of a repository routed to an upstream, or one nothing was pushed to, now lists the upstream's tags (every page it sends, on its own origin) merged with NORA's, paged as before; it listed only what NORA had cached. An upstream that fails leaves the local tags, or 502/503 when there are none (not 404); the answer is kept in memory, reused within a positive `metadata_ttl` and served stale under `serve_stale`. Upstream bearer tokens are now cached per credential too: two upstream entries on one url with different credentials no longer share a token.
