**Docker quarantine no longer breaks old images and floating tags under enforce (issues-maestra#1649)** — an old Docker Hub tag has no `digest` in the tag API, so an image from 2020 was held as new: its `images` now stand in for it. A digest reference to Docker Hub or quay had no tag to ask about and was always first-seen: NORA now searches the newest tags for it, bounded and once per digest. A tag that moved to a held digest answered 403 with no fallback, and the held manifest overwrote the admitted tag copy: the tag now keeps answering with the admitted copy until the new digest matures, says so in `x-nora-quarantine-held`, and counts `nora_docker_quarantine_tag_held_total`. A brand-new tag and a digest reference to a held digest stay a 403. After a restart an uncached blob of an image older than 90 days was refused and started a new TTL, because its ledger entry was gone: serving the cached manifest now admits what it names.
