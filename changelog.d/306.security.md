**deb proxy: a pool file is judged by its date, across every repository's holds (#306, audit A044)** — a `.deb` download was refused only when the requesting repository's own held-version map listed it, so a version published after NORA's last look at its suite, a file of a suite NORA never built, or a pool served through another `[deb.proxies]` entry than the one whose suites list it downloaded without a release-age check. A download now consults the holds of every `[deb.proxies]` repository and passes when any ledger dates the file. A `.deb` of a configured architecture or `_all` that no ledger dates first refreshes the built suites (under `metadata_ttl`), then is judged by `[curation.deb] unknown_date`: the default `log` serves it and logs `[AUDIT] deb: undated pool file` with `nora_curation_unknown_release_date_total{registry="deb"}`; `hold` refuses it. `.udeb` and other architectures are unchanged. Count the logged files before setting `hold`: under it, direct pool fetches from suites NORA never built and from pool-only entries answer 403 (the bypass token or a `[curation.deb] allow` entry passes them).
