**Docker upstream token realms are bound to the upstream (audit A014, A055, A062, #275)** — NORA now asks a bearer-token realm only on the upstream's own origin, or over https on a host listed in the new `[[docker.upstreams]] token_hosts` (`registry-1.docker.io` → `auth.docker.io` built in); before, any realm named in a 401 challenge got the upstream's credential and its answer was used as the upstream's bearer token. A realm with a fragment is refused, the service/scope query is URL-encoded, the token request no longer follows redirects, the token answer and the public.ecr.aws date answer are read with a running byte cap (1 MiB and 32 MiB) even without a declared length, and the token cache holds at most 4096 entries, with expired ones swept by the maintenance tick. Operators: an upstream whose token server sits off its own origin must list that host in `token_hosts` (chart `config.docker.upstreams[].token_hosts`), otherwise its cold pulls answer 502 and a warn names the host.
