**OIDC `namespace_scope` entries can be bound to one registry format (Maestra fork, audit A021, #305)** — a scope entry was a bare glob checked against whatever coordinate a write carried, so an entry written for raw paths, Maven groups or NuGet IDs also admitted the same string as an npm package, cargo crate, PyPI project, NuGet ID, Maven group, docker image or deb/rpm/apk repository. An entry may now be written `<format>:<pattern>` (`raw:vscode/**`, `maven:io/delta/**`, `nuget:mindbox.*`, `npm:@mindbox-cloud/*`, `pypi:python-mindbox-sdk`), where the format is a registry name as in `[registries] enable`; it admits writes to that format only, in provider and role-rule scopes alike. An entry without a prefix keeps admitting every format, so existing configs behave as before. Operators: config load refuses an entry whose prefix is not a registry format, and warns for an enforced provider that still has entries without a prefix (other than the bare `*`); deny log lines now carry `registry`. Rewrite the scopes with prefixes, giving every format a rule really writes its own entry, before relying on the binding.
