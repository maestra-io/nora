**Docker reads a config blob for its os/arch only when it is at most 4 MiB, and `/v2/_catalog` is served from the repository index (Maestra fork, maestra-io/nora#267)** — the image metadata written on a manifest push or a proxy fill read the referenced config blob whole and parsed it into a JSON tree, without checking its digest or size. It now reads only a valid digest whose blob is at most 4 MiB, and parses only `os`, `architecture` and `variant`; a larger blob leaves os/arch "unknown" in the UI, and the push itself is unchanged. `GET /v2/_catalog` listed every key under `docker/` on each request; it now answers from the shared repository index (one background rebuild at a time), is eventually consistent with pushes, answers 503 with `Retry-After: 30` until the index is first built after a start, and pages with OCI `n`/`last` and a `Link` header like `tags/list`. The Maven and Go UI root pages are built from their repository indexes too.
