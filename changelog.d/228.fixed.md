**Quarantine: an incomplete ledger and a restore no longer hold mature copies again (#228)** — after a start whose ledger load did not read every entry (a failed listing, an unreadable entry), an enforcing gate answered 403 for a digest with no record in memory, though the ledger in storage might hold it as mature: it now reads that digest's own entry (one GET, kept in memory), and answers 503 with `Retry-After` when the store does not answer. `nora restore` and `nora migrate` wrote every object now, so a copy cached more than 90 days ago (dated by its write time once the ledger forgot it) was held for a new TTL: backups now keep each artifact's write time (`write_times` in `metadata.json`), and restore and migrate carry it in `.nora-quarantine/written/<digest>` entries. Older archives restore as before.
