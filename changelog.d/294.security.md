**Docker: a push of a bare name no longer answers the name a prefix or registry host routes; UI directory pages read the index at every depth.** Under `default_action = "allow"`, a bare name and the name that a prefix or served registry host routes to the fallback upstream share their storage keys. So a push of `team/app:tag` was what every pull of `<prefix>/team/app:tag` got, even though A011 refuses that push under the routed name. Now such a routed name is answered by the upstream's copy unless `curation.internal_namespaces` lists it. The bare push does not answer it, its bare manifest does not answer it, and the push does not date it. The bare name still answers its push. Names bound by `namespaces` and deny-mode deployments, which have no writable bare twin, are unchanged. The UI pages that used to list their whole storage prefix on every request are now built from the repository index, as the root pages are: the Maven and Go directory pages below the root, and the Ansible root and namespace pages. Only a Maven directory of files and a Go module page list storage, and only their own files. The Ansible index now holds one entry per collection (`{namespace}/{name}`) instead of a single `download` entry, so its repository count is the collection count. A new test fails if the GC mark phase keeps parsed manifests instead of their references. **Behaviour change:** after a bare push, a pull of the routed name fetches the upstream's tag again, because the push removed its cached copy. While the upstream is unreachable, that pull fails like any other upstream miss. A routed name with a bare twin that is removed from `internal_namespaces` stops answering with the tags pushed to it. A Maven or Go path missing from the index shows an empty page until the next index build. (audit A011, A029, A053)
