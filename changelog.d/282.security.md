**Maven: uploads only under hosted groups; checksum files are computed, never stored as sent; a deploy and a fill of the same file are serialised (Maestra fork, maestra-io/nora#282, audit A017, A035)** — with `[maven] proxies` configured, any Write credential could upload under any coordinate NORA had not cached yet, and that file was then served instead of the upstream's; a checksum uploaded before NORA held one was stored as sent beside any artifact. Now an upload is for a coordinate under `curation.internal_namespaces` or the new `[maven] hosted_groups` (same glob syntax, e.g. `"io.delta.**"`); outside them `hosted_groups_enforcement = "warn"` (the default for this release) stores it and logs a `[SECURITY] Maven upload outside` WARN, `"enforce"` answers 403, and both count `nora_maven_unhosted_uploads_total{outcome}`. A registry without proxies is unchanged. An uploaded `.md5/.sha1/.sha256/.sha512` is compared with the stored artifact's digest and the computed value is stored: 404 when the artifact is not stored (before, the client's value was kept), 400 on a mismatch. A release deploy also takes the file's own publish lock, the one a spooled proxy fill holds, so a fill that started before the deploy can no longer replace the deployed file and its pin afterwards. Operators: add every group you deploy to (the WARN lines name them) to `hosted_groups` before switching to `enforce`.
