**npm deprecate keeps the document and packument limits, `import_embedded` names publish again, SNAPSHOT metadata under exact Maven hosted patterns (Maestra fork, follow-up to audit A092, A091, A017, #308)** — `npm deprecate` checked only the size of each `deprecated` message, so the version document it rewrote could pass `npm.max_document_kb` and the packument it regenerated could pass `npm.max_packument_mb`; now the rewritten version document is checked too, and a deprecate that grows the packument past the limit answers 413 with every version document put back (clearing messages is always let through, so an oversized packument can be brought back under). A package listed in `npm.import_embedded` publishes without also being in `curation.internal_namespaces`, as before #283: the first publish of such a name was answered 403. Under `maven.hosted_groups_enforcement = "enforce"`, a SNAPSHOT version's own `maven-metadata.xml` (and its checksums) now counts as the artifact's coordinate, so an exact `group:artifact` or a `group:*` pattern in `maven.hosted_groups` or `curation.internal_namespaces` admits the whole SNAPSHOT deploy instead of refusing its metadata with 403 (under `warn` it was a false `[SECURITY]` WARN).
