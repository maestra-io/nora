**Galaxy tarballs dated without prior metadata; Galaxy listings keyed and forwarded by their paging only (Maestra fork, audit A036, A037, A067)** — a collection tarball was dated only by Galaxy metadata NORA had already cached, so a tarball asked for before its version detail, or a copy cached without one, was not dated and `min_release_age` let it through. With trusted upstream dates and an Ansible release age, a missing version detail is now fetched (and cached under the key `version_detail` reads) before the download is judged, a copy cached without one is dated no earlier than its write time, and a date still unknown goes through `[curation.ansible] unknown_date` (`log` by default: served, logged and counted in `nora_curation_unknown_release_date_total{registry="ansible"}`; `hold` refuses it). The collection and version listings now send upstream only the percent-decoded, normalised `limit`, `offset` and `page` values, and key their cache by the same pairs; before, other parameters and other spellings of them reached the upstream while the cache key ignored them, so one request could replace the listing every client got. Operators: a tarball younger than the release age fetched straight from its download URL is now refused; `limit` is part of the listing key, so each collection's listing is fetched upstream once after the upgrade (old `*-page-N.json` entries are no longer read); filters on `/collections/` (`namespace=`, `q=`, `ordering=`) are no longer forwarded.
