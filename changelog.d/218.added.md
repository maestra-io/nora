**`nora migrate --delete-extraneous`, and local storage fails closed on a pin log it could not load (Maestra fork, maestra-io/nora#218)** — `nora migrate` keeps destination keys the source deleted since an earlier run; the new opt-in `--delete-extraneous` deletes them after a copy without failures (with `--dry-run` it only lists them as `Would delete extraneous <key>`), never for an empty source. On local storage a start that could not read the whole `.nora-pins.ndjson` still starts, now sets `nora_hash_pin_log_incomplete` to 1 and refuses reads of keys without a loaded pin as integrity violations until a start reads the whole log (before: served unchecked). A last line cut by a crash mid-append no longer counts as an incomplete log.
