**Undated Terraform providers and modules are judged; module versions are dated (Maestra fork, audits A082, A083, A067)** — a provider version the registry.terraform.io `/v2` API left undated (a failed lookup, or an answer without the version) was served undated, so `min_release_age` let it through; a cached provider file never asked for its date at all; and module downloads and archives were never dated. A provider version without a `/v2` date is now judged by `[curation.terraform] unknown_date` on its download metadata, archive and mirror `{version}.json`, and hidden from `versions`/`index.json` when held; a cached archive is dated by `/v2` while a release age is set, else by the write time of NORA's copy. The last dated `/v2` answer of a provider is kept at `terraform/_v2-dates/<ns>/<type>.json` and dates the versions it listed while the API is down. A module version is dated by its `published_at` (`/v1/modules/<ns>/<name>/<system>/<version>`) on its download, and on its archive when the archive is not cached; without it, the write time of the cached source address, then `unknown_date`. A module version list hides the versions the registry's `/v2` module API dates younger than `min_release_age`. Operators: under the default `log`, an undated version is served with a `[SECURITY] min-release-age unknown date` line and `nora_curation_unknown_release_date_total{registry="terraform"}`; a module version younger than `min_release_age` is now refused (403), as is a version whose only date is a copy NORA cached less than `min_release_age` ago. Set `unknown_date = "hold"` (`NORA_CURATION_TERRAFORM_UNKNOWN_DATE=hold`) after watching the counter; a `[curation.terraform] allow` entry or the bypass token unblocks a build.
