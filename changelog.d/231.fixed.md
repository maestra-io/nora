**A Basic username with an empty password is no longer logged as a wrong password (#231)** — uv with a keyring provider sends `token:` to every new URL and retries with the real token after the 401, and the .NET SDK sends `:` the same way. NORA logged each first round as `wrong_password`: 43k WARN lines a day on packages.maestra.io, which buried the real wrong credentials. An empty password is now refused before any store is read, never counts toward the lockout, and is counted as `nora_auth_rejected_total{reason="no_password"}` without a log line, like the anonymous challenge. The response is the same 401.
