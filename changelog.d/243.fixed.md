**Docker GC: a manifest that is not a JSON object keeps only its own repository; the mark phase keeps digests, not documents (Maestra fork, audit A028, A029)** — one stored manifest key that did not parse to a JSON object stopped Docker orphan collection in every repository. Such a manifest now keeps every object of its own repository (and of its legacy un-namespaced form), counts in `nora_gc_docker_mark_failures_total` and logs its key; every other repository is still marked and swept. A listing or read error still keeps every Docker object for the pass. The mark phase no longer holds every parsed manifest until the walk ends: it keeps each manifest's digest-shaped references (at most a sha512 digest long), so a pass holds one parsed document at a time. The scheduler's `GC scheduler: done` line now reports `docker_mark_failed`, `nora gc` prints `Docker sweep: incomplete` instead of `skipped`, and the new `NoraGcDockerMarkFailed` alert fires on any increase of the counter in a day. Where a manifest of this kind is already stored, the first pass after the upgrade also removes the orphans of the other repositories that earlier passes kept; run `nora gc` (a dry run) first to see them.
