**A spooled proxy artifact keeps its spool budget until its response ends (Maestra fork, audit A071)** — a cold miss above `server.stream_threshold_mb` is spooled to disk under `server.spool_max_mb`, but the response read the spool file through a bare handle: once the background cache write was done the file was unlinked and its budget returned while an unfinished response still held the bytes on the spool volume, outside the budget and out of a directory listing. The response body now holds the spool, both for a body answered whole (NuGet, npm, PyPI, apk, Maven, helm, GitHub) and for a cold miss streamed while it downloads (helm, apk, GitHub), so the file and its reservation last until the body is sent or dropped. Operators: every in-flight response of a large cold miss now counts against `spool_max_mb` for its whole transfer, so a burst of slow clients reading large cold artifacts can answer later large cold misses 503 with `Retry-After` (`nora_spool_failures_total{reason="busy"}`) instead of overfilling the spool volume. Single-flight followers share one spool, cache hits are not spooled, and a live cold miss under the threshold still falls back to memory when the budget is busy.
