**apt proxy trusts only valid upstream signing keys, per repository (audit A050, A051, maestra-io/nora#241)** — a filtered `[deb.proxies]` repository used to accept an upstream `InRelease` signed by any key of the shared `deb.upstream_keyring_dir`, including a revoked or expired key, a non-signing subkey or an expired signature, and a signed Release of another suite, then re-sign it with NORA's key. Now a revoked key is left out of the keyring at load (logged), a signature counts only when it is unexpired and made by an unexpired signing-capable key (gpgv's rules; a primary key without key flags still signs), the Release's `Suite` or `Codename` must be the requested suite, and the new `deb.upstream_keyrings` (repo → keyring file or directory) binds each repository to its own keys; repositories without an entry keep the shared directory, with a startup warning when several share it. A refused refresh keeps the last good build served.
