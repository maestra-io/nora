**Hosted-or-proxied without a LIST per request (Maestra fork, maestra-io/nora#180)** — whether a NuGet ID is imported, an npm package published here or a PyPI project NORA's own was one storage LIST (an S3 round trip) on every metadata request, almost always answering "nothing here". An empty listing is now remembered in memory for 30 s (a non-empty one never is), so five requests for a proxied name cost one LIST instead of five. A write under the prefix through the same process voids it before the write returns, so the replica that acknowledged a publish never answers the name as proxied afterwards; a write by another process (a second replica, `nora import`, a restore) is seen after at most 30 s.
