**An apk version is dated by the later of its build time and NORA's first sight, an older index generation is not taken, and an RSA256 signature wins over SHA-1 (audit A038, A086, B20)** — `min_release_age`, the download check and the quarantine seed dated an apk version by its `t:` build time alone, so a version first listed today with an old `t:` was served at once. Each index entry now records when NORA first saw it listed (the entries of the first index NORA reads of a repository, and every entry cached before this change, count as seen before NORA), and the later of the two dates it. A refreshed `APKINDEX.tar.gz` whose newest build time is older than the cached index's is now refused: the cached generation keeps being served (marked `x-nora-stale`, regardless of `serve_stale`), stored again so the refetch waits `metadata_ttl`, and counted in `nora_upstream_index_older_refused_total{registry="apk"}`. An index carrying both a `.SIGN.RSA256.` and a SHA-1 `.SIGN.RSA.` signature is verified by the RSA256 one; SHA-1 alone is still accepted, as Alpine signs its indexes. Operators: a version that appears upstream with an old build time now waits `min_release_age` from first sight (the curation `allow` list releases it early), and when an upstream removes its single newest package without adding a newer one the cached index stays until its next upload.
