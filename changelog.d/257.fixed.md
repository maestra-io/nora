**A broken working-directory `config.toml` refuses the start; the chart moves detailed `/health` and `/metrics` to an internal port by default (Maestra fork, audit A027, B09, B12, B24)** — with `NORA_CONFIG_PATH` unset, a `./config.toml` that is present but not valid TOML or not readable started NORA on built-in defaults (authentication and curation off); it now exits with `EX_CONFIG` (78), as the file `NORA_CONFIG_PATH` names already did. Only an absent file still starts on defaults. A reload (SIGHUP) without `NORA_CONFIG_PATH` is refused and keeps the running curation policy when `./config.toml` is absent or unreadable, instead of installing defaults. Before upgrading a packaged install that reads `./config.toml`, check that the file parses and is readable by the service user. The Helm chart now sets `config.server.internal_port: 9100`: the `http` port serves the status-only `/health`, `/ready` and a 404 for `/metrics`, the Service gets a port `internal`, and the ServiceMonitor scrapes it; scrapers of your own must target port 9100 (and a NetworkPolicy must admit them), or set `internal_port: null` to keep the old shape. The `deploy/traefik.yml` example no longer redirects all of `:80` to https, so API clients configured with `http://` get a 404 instead of a redirect that hides cleartext credentials; switch them to `https://`. An optional UI-only redirect router is in the example. `docs/supply-chain-controls.md` records why NORA does no in-line antivirus scanning and which controls cover ASVS V5.4.3.
