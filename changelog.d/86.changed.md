**API tokens in the storage backend (Maestra fork, maestra-io/nora#86)** — each token is one immutable object `.nora-tokens/<16hex>.json`, created with `put_if_absent`, and last-use times go to one `.nora-tokens/last_used.json` written by the 30 s flush. A cache-miss verify is one storage read. The `<16hex>.json` files in `auth.token_storage` are imported at each start, each at most once (`.nora-tokens/legacy_imported.json`), so a token revoked after its import stays revoked; files are left in place and a missing directory is fine. `nora backup`/`migrate` carry the tokens, `migrate` deletes destination records the source no longer has, and `nora restore` writes an older archive's `.nora-local/tokens/` records into storage. Before, tokens were files on the local volume, so `storage.mode = s3` still needed a PersistentVolume, and the flush rewrote every active token's file, which could bring back a token revoked between its read and its rename.
