**The concurrent publish tests force the race they check (Maestra fork, maestra-io/nora#225)** — the maven-metadata.xml, pypi requires-python and npm packument tests ran the publishes at once and relied on the scheduler to interleave them, so with the lock removed they still passed when storage was fast. Each now holds the first publish between its read and its write while the others run (a test-only storage hook, paused clock), so a missing lock fails them on every run; the npm test also checks the stored packument, which a read would otherwise rebuild.
