**Conan and pub: a file is dated by its own revision or version, and pub refreshes a listing that does not date the archive** — with `trust_upstream_dates`, every Conan recipe and package file was dated by the reference's cached `latest.json`, whatever revision it belonged to, so a new revision could pass `min_release_age` and mature in the quarantine on an older revision's date; a pub archive was dated only by the stored package listing, so a version that listing did not date was served undated. Now a Conan file is dated only by its own revision: the recipe's or the package's `latest.json` when it names that revision, else that revision's row in `revisions.json`, else no date (the quarantine counts from NORA's first sight). A pub archive of a proxied, non-internal package whose stored listing does not date the version fetches the listing from the upstream again and stores it; a date still unknown, on either format, is judged by `[curation.<registry>] unknown_date` (default `log`: counted in `nora_curation_unknown_release_date_total` and left to the quarantine; `hold` refuses it while `min_release_age` lasts). A pub listing row without a `version` no longer ends the date lookup. **Action may be needed:** where Conan or pub runs an enforcing quarantine, a file whose own revision has no cached listing is held until `quarantine_ttl` passes; enable those quarantines in observe mode first.
