**Cargo: a first publish does not claim a crate name the upstream serves; release dates of new versions are read, not skipped; a proxy fill never replaces a published crate (Maestra fork, audit A005, A006, A035)** — with `cargo.proxy` set, the first publish of a crate name made it NORA's: from then on its index listed only the published versions, so any Write credential could shadow a crates.io crate. That first publish is now a 403 naming `curation.internal_namespaces` unless the name is listed there or in `cargo.import_embedded`, or the publish imports an index NORA already holds as the crate's own (a listing error is a 503); new versions of crates published here and registries without an upstream are unchanged. A download of a version missing from the cached `cargo/<crate>/metadata.json` refetched nothing, so every version released after the crate was first cached was undated and passed `min_release_age`; such a copy is now refetched once it is older than a miss TTL of 60 s (capped by `cargo.metadata_ttl`), as PyPI does, and a date still unknown is judged by `[curation.cargo] unknown_date` (default `log`: served, logged and counted in `nora_curation_unknown_release_date_total{registry="cargo"}`; `hold` refuses it). A version published here (its index entry) is never dated upstream nor judged. The `.crate` fill of a proxied download is create-only, so a publish of the same version that lands first is kept. Operators: before rolling out, add every crate name you publish here to `curation.internal_namespaces` (exact names; dotted patterns never match a crate name); a version under `min_release_age` that was served before because its date was missing is now refused until it ages or is allowlisted; a stored `.crate` that fails its pin is no longer healed by the next fill.
