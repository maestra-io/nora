**Docker quarantine dated by ghcr.io, mcr.microsoft.com, public.ecr.aws and Artifact Registry (issues-maestra#1649)** — under `trust_upstream_dates` these registries had no date source, so every image from them was "new to this mirror" on its first pull (actions-runner 2.338.2, published 26.10, read as held until 08.11). ghcr.io is dated by the GitHub packages API `created_at` of the digest's package version (needs the new `[[docker.upstreams]] date_token_file`, re-read at each walk), mcr.microsoft.com by the catalog's `lastModifiedDate` of the tags naming the digest, public.ecr.aws by the gallery's `imagePushedAt`, Artifact Registry (`*-docker.pkg.dev`) by tags/list `timeUploadedMs`. Each date is server-side and bound to the digest, so a re-pushed tag gets the new digest's date; a digest request is dated too. The listings are walked once per repository on their own task (bounded pages, 120 s, kept 10 min, a failed walk retried after 1 min) and a request waits at most 5 s for one: a failure, rate limit or unknown digest leaves first-seen and never passes an image. A digest already held by NORA's own clock is asked about again when a tag pull revalidates it and moves back to the registry's date, with what it names (not Docker Hub or quay.io, which date a tag; in memory only, the next tag pull after a restart finds it again). `nora_docker_quarantine_first_sight_total{source}` gains `ghcr_created_at`, `mcr_last_modified`, `ecr_public_pushed_at`. The date lookup's body cap rises from 8 to 32 MiB (the dotnet/aspnet catalog is 6.9 MB).
