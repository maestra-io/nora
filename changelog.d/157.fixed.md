**Local storage: no false `INTEGRITY VIOLATION` on a concurrent overwrite, and the pin log survives a damaged line (review round 4)** — the buffered read of a key paired a new body with the old pin when it landed between a write's rename and its pin append: it now waits for the write, as the streamed reads do. At start the pin log (`.nora-pins.ndjson`) was read up to the first line that did not parse and then compacted from that partial set, or deleted when the file could not be opened, which left every later artifact unpinned for good: a bad line now costs that line only, and a log that was not read in full is never compacted or removed. Pin appends no longer hold readers on a slow disk, the log is compacted while running once it holds more than twice its live entries, per-key commit locks are pruned every 5 minutes instead of kept for the life of the process, and a copy onto an existing key replaces it with a rename instead of remove-then-link.
