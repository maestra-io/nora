**NuGet: an audit-mode namespace scope no longer claims a proxied ID; versions brought in by `nora import` can be unlisted; the import tool refuses npm entries without a source digest.** The first push of an ID the feed proxies is allowed to a namespace-scoped OIDC caller only when the ID matches every pattern set of its scope. Before, any scoped caller could claim it, so a provider with `namespace_scope_enforcement = "audit"` (which lets out-of-scope pushes through and only counts them) could make the first push of a public ID such as `Newtonsoft.Json`. `DELETE`/relist of a version that only `nora import` records hold, with no state document yet, now carries the imported versions into a document first, as a push does, and answers 204/200 instead of 404; the daily nuget.org sync no longer fails on such versions. `maestra/scripts/import/import.py` now fails an npm version whose entry has neither a sha512 `integrity` nor a `shasum` before downloading it, as it already did for NuGet and PyPI. **Behaviour change:** with an audit-mode scope, the first push of a proxied ID outside the scope answers 403 (an Admin token, `curation.internal_namespaces`, or an in-scope ID still claims it). The first unlist of an imported-only ID writes its state document.
