**The NuGet sync and the Artifactory import push only digest-checked, allow-listed, cooled-down versions, with hash-pinned dependencies (#268, audit A002, A102, A103)** — `maestra/scripts/import` took nuget.org versions for every in-scope `Mindbox.*` ID found on Artifactory and pushed entries that carried no source digest after only a zip check, the daily `maestra-sync-public-ids` job imported a nuget.org release on the day it appeared, and both that job and the CI script tests installed `requests` by version with floating, unhashed dependencies. Now nuget.org versions are added only for IDs in `public-ids.txt`, each with its catalog sha512; an entry with no source digest is failed, never pushed; the full import reads PyPI only from the repository named in the required `ART_PYPI_REPO`; `enumerate.py --min-age` (default `3d`, as `curation.nuget.min_release_age`) defers a version until its catalog leaf `created` (else `published`) is that old, an undated one waits; a listed ID nuget.org does not know stops the run; and a hosted version nuget.org has unlisted is unlisted in nora. `maestra/scripts/import/requirements.txt` pins every dependency by version and file sha256 and is installed with `--require-hashes --only-binary=:all:`; `check-upstream-workflows.sh` fails CI on a `pip install` without `--require-hashes`. Operators: new public `Mindbox.*` releases reach nora about 3–4 days after publication; dispatch the sync with `min_age=0d` to import one at once. The sync goes red on a listed ID missing from nuget.org (serving is unaffected).
