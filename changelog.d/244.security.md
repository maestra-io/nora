**NuGet: the first push of a proxied ID needs an Admin token; a push keeps imported versions (Maestra fork, audit A096, A097)** — with an upstream configured, any Write credential that is not namespace-scoped (an `nra_` token, an htpasswd user) could push the first version of any ID, and from then on that ID was served from the pushed feed only, replacing the proxied package for every consumer. Now the first push of an ID that is neither pushed nor imported here and is outside `curation.internal_namespaces` answers 403 unless the caller is Admin or OIDC namespace-scoped; the body names both remedies (an Admin push, or adding the prefix to `internal_namespaces`). Once hosted, Write credentials push its next versions as before; auth off or no proxy is unchanged. Separately, a push to an ID brought in by `nora import` used to accept other bytes for an imported version (201) and hide every other imported version behind the new state document. Now an imported version is immutable like a pushed one (other bytes 409, identical bytes 200 with nothing written), and the first push of a new version copies the imported versions into the state document, so all of them stay listed and served. A listing or copy failure during that push is a 503, never a partial document.
