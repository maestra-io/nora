**A Maestra image is pushed and signed only from the protected `nora-release` environment, for an anchored release tag (audit A016, #258)** — `maestra-release.yml` already refused a tag off `maestra/main` and ran CI on it (#151), but those checks live in the tagged commit's own copy of the workflow. Job `image`, the only one that gets ECR push credentials and signs, now runs in the GitHub environment `nora-release`, whose OIDC claim the Teleport image-push token can require. The tag check is anchored to `v<version>-maestra.<n>` (the old glob let `v1.4.3-maestra.15-x` through as an image tag) and runs first in `verify`, which also refuses a branch ref. A dispatched re-run is now `gh workflow run maestra-release.yml --ref <tag>` (the `tag` input is gone). `check-upstream-workflows.sh` (CI `coherence`) fails when the image job loses the environment, `needs: [verify, ci]` or the anchored check.
