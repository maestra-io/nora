**Hosted NuGet lookups re-check storage; internal IDs stay out of upstream search (Maestra fork, maestra-io/nora#9999)** — the hosted feed's in-memory index now re-reads an ID's state document at most every 30 s on access (single-flight per ID), so a push, new version or unlist written by another process over the same storage is served within 30 s instead of at the next retention pass or admin reindex; a storage error during a re-check keeps the previous answer. The re-check of an ID with no state document takes no per-ID lock, and the remembered absences are capped, so requests for arbitrary IDs cannot grow memory. Search and autocomplete check every package-ID-shaped token of the query string (`q` terms such as `packageid:X`, `id:X` or `"X"`, `?id=`, any other key or value) against `curation.internal_namespaces`, and a query naming an internal ID is answered locally only; autocomplete `?id=` for an internal ID answers from its hosted or imported records, or with no versions. Before, only the whole `q` string was checked, so a prefixed or multi-term query, or `?id=`, sent the internal ID to the upstream search services.
