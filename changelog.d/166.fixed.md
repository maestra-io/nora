**Storage and upstream faults are no longer answered as "not found" in deb/rpm, pub, gems, cpan, ansible and cargo; raw and Maven fixes (Maestra fork, maestra-io/nora#166)** — a proxied deb/rpm repository answered 404 for any upstream failure without a cached copy; now only an upstream 404 is a 404 (502/503/504 otherwise). Cache reads in pub, gems, cpan, ansible and the cargo sparse index answer 503 when the store cannot be read instead of treating it as a miss. Raw: HEAD runs the curation gate GET runs, DELETE takes the publish lock, `If-None-Match` is a weakly compared list, and an invalid `raw.cache_control` is a config warning (an error under `NORA_CONFIG_STRICT`) instead of a panic on every request. Maven: a mismatching client checksum removes the artifact just stored (within 10 minutes of its upload) so the deploy can be retried instead of meeting `immutable_releases`, and digests compare case-insensitively without the file name. npm publish fails, and is undone, when a dist-tag it would move cannot be read.
