**Proxy paths the upstream URL parser reads differently are refused (Maestra fork, maestra-io/nora#233)** — curation, the internal namespaces, the release-age gate and the storage key judged a decoded request path that was then formatted into the upstream URL, where the parser strips tab, LF and CR (`.<TAB>.` turns into `..`), trims spaces and ends the path at `#` or `?`: the coordinate judged was not always the one fetched. The edge now answers 400 to a path holding an encoded or literal control byte (`%01`-`%1F`, `%7F`), and the Go, Maven, npm, PyPI, cargo, CPAN and deb/rpm pull-through handlers answer 400 to a decoded path with a control byte, space, `#` or `?` before curation, storage or the upstream see it. A NuGet flat-container download now requires a NuGet id and version and the file `{id}.{version}.nupkg` or `{id}.nuspec`; an npm tarball path must name a package `pkg` or `@scope/pkg` (or `-`), and only direct `versions/<v>.json` children mark an npm package as published. Hosted deb/rpm uploads, deletes and reindexes refuse a control character in the repository name or path, a reindex never adopts a stored key holding one, and the deb index rebuild leaves out (with an error log) a record whose file name holds one instead of signing it into `Packages`. Raw and other hosted keys keep accepting spaces.
