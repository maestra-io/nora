**Docker quarantine judges cache hits while the ledger loads, bounds what one manifest records, and dates an index only by the images a tag lists (audit A058, A059, A015, #278)** — while the quarantine ledger was not in memory whole (the background load after a start, or a walk that failed or timed out), a cached manifest or blob with no record in memory was served as unrecorded and its verdict header read `mature`; the cache-serve gate now reads that digest's own entry object first (one storage GET), so a held digest is refused under `enforce` and reported `pending` with its `x-nora-quarantine-until` under `observe`, and an entry the store cannot read is a 503 with `Retry-After` under `enforce`. One proxied manifest used to record a ledger entry and a stored object for every digest it named, bounded only by the 4 MiB body; a manifest naming more than 1024 digests, or a document with neither `schemaVersion` nor `mediaType`, now records only itself (a warn log names the count) and each child is dated by its own fetch. On Docker Hub an index entry annotated as an attestation was left out of the tag check whatever its platform; only BuildKit's `unknown/unknown` form is left out now, so an index whose other entries a tag does not list falls back to NORA's first-seen date.
