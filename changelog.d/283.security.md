**npm: a first publish outside `curation.internal_namespaces` does not take a name an upstream serves; publish documents have size limits** — any Write credential without a namespace scope could publish a name the npm upstream also serves, and from then on every client got the published copy instead of the upstream package; a publish could also replace a tarball cached from the upstream. Now, when an upstream serves the name, its first publish passes only when the name or its scope is in `curation.internal_namespaces`; otherwise it answers 403 naming that setting, logs a `[SECURITY]` WARN and writes a `publish_refused` audit record (with `curation.mode = "audit"` it only logs the WARN), and 503 while the published versions cannot be listed. A name already published here keeps publishing, and a name no upstream serves is unaffected. A publish over a tarball cached from an upstream answers 409 unless the name is internal. Separately, a publish stored version documents, the readme and the deprecation message of any size up to the request body limit, and the packument assembled from them had no total bound: `[npm] max_document_kb` (`NORA_NPM_MAX_DOCUMENT_KB`, default 8192) and `max_packument_mb` (`NORA_NPM_MAX_PACKUMENT_MB`, default 128) now refuse a larger one with 413 before anything is stored (the packument check rolls the publish back); 0 turns a limit off, and packages already stored are served whatever their size. **Action may be needed:** a CI job that first-publishes a new name an upstream also serves needs that name or its scope in `curation.internal_namespaces`; a package whose documents are over the defaults needs a higher limit. (audit A091, A092)
