**Teleport app traffic gets its own listener that never trusts forwarding headers (audit A007, maestra-io/nora#246)** — the Teleport app agent reached nora on the main port from inside `auth.trusted_proxies`, so the `X-Forwarded-For` / `X-Real-IP` it relayed chose the client address that keys the rate limiters and the logged `client_ip`. The new `server.teleport_port` (`NORA_TELEPORT_PORT`, chart containerPort `teleport`) serves the same routes but drops both headers before anything reads them, so every request there is keyed by its TCP peer; it must differ from `port` and `internal_port`. The new `auth.teleport.accept_on_main_port` (default `true` for the switch-over) keeps honouring `Teleport-Jwt-Assertion` on the main port; set it to `false` once the Teleport app targets `teleport_port`, after which the header counts only there. Registry traffic on the main port is unchanged.
