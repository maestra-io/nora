**The outbound guard holds beside a partial proxy setup and for upstream-named endpoints; the startup check names every private upstream (#297, audit R07, R08, R09)** — the guard that keeps the server's upstream clients off loopback, private, link-local and metadata addresses (#236) was left out whenever any of `ALL_PROXY`, `HTTPS_PROXY` or `HTTP_PROXY` was set, although reqwest still connects directly for a scheme no variable proxies and for a `NO_PROXY` host: those direct connections are now guarded as without a proxy, and only the proxies' own host names are resolved unfiltered, so a proxy on a private address keeps working. A NuGet search or autocomplete endpoint discovered from a non-default feed's service index is no longer taken when it is a loopback/private IP literal off the feed's own host, unless `server.allow_private_upstreams`. The startup warning that names `server.allow_private_upstreams` now covers every upstream the shared clients fetch from, a `localhost` upstream and the helm, hf and apk upstreams included, so an upstream the guard refuses after an upgrade is named in the log instead of failing silently.
