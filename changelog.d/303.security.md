**Helm release age is no longer earlier than NORA's first sight of a chart version (audit A068)** — in a `[helm] trust_created` repo the release age and, with `server.trust_upstream_dates`, the quarantine's first-seen time came from the index `created`, which the publisher writes: a new version with a backdated or missing `created`, or an old version re-pushed with other bytes, was listed, served and recorded as mature at once. NORA now records when it first saw each version's digest in a refreshed index (`.nora-first-seen/helm/index/<repo>.json`, carried by backup and migrate) and dates a version no earlier than that, so such a version is left out of the index and refused until `min_release_age` has passed. The repo's first fetch records nothing, so no listed history becomes young on upgrade or when a repo is added; versions with honest dates see no change. The ledger is written before the refreshed index, and while it cannot be written the cached index stays in service.
