**apt proxy refuses older upstream generations and never reads unreadable state as empty (audit A043, A048, A049, A086, maestra-io/nora#276)** — a filtered `[deb.proxies]` repository rebuilt from any validly signed upstream `InRelease`, also one older than the build it served, re-signed it, and dated the versions it had dropped as new when they came back; an unreadable or unparsable first-seen ledger dated its whole index "before NORA", and an unreadable held-version map was rewritten from empty, both releasing held versions for good; an index missing upstream for one build lost its holds. Now an upstream `Release` whose `Date` is older than the served build's is refused (a missing `Date` is not compared), a re-listed file keeps its first date, a ledger or held-version map that cannot be read fails the rebuild (logged at error level with the key, the last build stays served, `.deb` downloads answer 503 when no held set was ever read), and a skipped index keeps its holds. Recovery for an object that stays unreadable is in docs/deb-proxy.md.
