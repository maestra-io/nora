**`nora migrate` and `nora backup` no longer report success over missing objects (review round 4)** — a migration skipped every key the destination already had, so a catch-up run left the first run's Docker tags, npm packuments and NuGet index files in place: a key is now skipped only when the destination holds the same bytes (equal SHA-256 pins). Both commands exited 0 when objects could not be read or written: they now exit non-zero and say how many failed, and a backup that misses objects is kept as `<output>.partial` instead of replacing the archive at the output path (`metadata.json` carries `failed_count`). On an object store, `stat` and `pin` of a key with `@` repeated the request under the pre-#534 `_at_` key after any error, a timeout included: they now do so only after NotFound.
