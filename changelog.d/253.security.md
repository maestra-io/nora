**Audit write records can no longer be rotated out by downloads; audit and log files are created 0600; the binary default audit mode is `both` (audit A018, B27, B28, maestra-io/nora#253)** — in `file`/`both` mode every download (`pull`, `cache_hit`, `proxy_fetch`, `curation_block`) shared one size-rotated `audit.jsonl` with pushes, deletes and token mints, so enough reads deleted the oldest write records. Reads now go to `audit-reads.jsonl`, rotated at half of `audit.max_size_mb` with the same `audit.max_files`; every other action, including any action not known as a read, stays in `audit.jsonl`, and disk use is bounded by `1.5 * (max_files + 1) * max_size_mb`. Tooling that looks for pulls in `audit.jsonl` must read `audit-reads.jsonl`. When the audit channel is full a write entry is now printed to stderr instead of being dropped (reads are still dropped). New and rotated audit files and the `NORA_LOG_FILE` file are created with mode 0600 (existing files keep theirs), so a reader running as another UID on a shared volume needs the file's mode changed. Without an `[audit]` mode the binary now writes to the file and to stderr (`both`, was `file`); `NORA_AUDIT_LOG=file` restores the old default. The Helm chart keeps `stdout`.
