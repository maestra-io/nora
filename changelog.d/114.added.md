**Docker quarantine dated by the registry's publish date (`trust_upstream_dates`, #114)** — the docker digest quarantine held every manifest NORA saw for the first time for `quarantine_ttl`, by NORA's clock, so an image published months ago was "new to this mirror" on its first pull. `[[docker.upstreams]] trust_upstream_dates = true` dates that first sight by the registry's own record of the push: Docker Hub `tag_last_pushed` and quay.io `last_modified` for a tag request whose tag still names the fetched digest, registry.k8s.io / gcr.io tags/list `timeUploadedMs` per digest. An image older than the TTL is admitted at once with everything it names; a fresh one is held from its publish date. No date, a future date or a failed lookup (429, 5xx, timeout) leaves first-seen and never fails the pull. Each first sight logs its `source` and counts `nora_docker_quarantine_first_sight_total{upstream,source,status}`; registries without a date (ghcr.io, mcr, public.ecr.aws) keep first-seen, and the flag there is a config warning. Off by default. Every manifest `GET`/`HEAD` now carries the verdict: `x-nora-quarantine: pending|mature` on a 200 (before, only the enforce 403 had it, so `observe` was unreadable), with `x-nora-quarantine-until` (unix seconds) while held; the 403 keeps its value and gains the same `until`.
