**GitHub Releases proxy: an asset whose name has a `+` is served.** The release record keyed each asset by the last segment of its `browser_download_url`, which GitHub percent-encodes (`%2B`), while the route hands over the decoded name, so every such asset answered 404 (all python-build-standalone archives, `cpython-3.12.16+20261110-…`). The segment is now decoded before it becomes the key. Records cached under `github/meta/` before the upgrade keep the old key until `metadata_ttl` refreshes them.
