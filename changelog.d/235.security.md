**Upstream release-date lookups are memoised, capped and behind their own breaker (audit A085, A055)** — the RubyGems versions API, the registry.terraform.io `/v2` API and the Maven Central HEAD/search were asked once per request that needed a date (terraform on cache hits and version lists too, gems and Maven on every cache miss), with no coalescing, no breaker, and the answer read whole into memory. Each lookup now goes through one memo: concurrent callers share one fetch, an answer is kept for the format's `metadata_ttl` and a miss for 60 s, and a version missing from a kept answer asks again at most once a minute. The fetches read at most 32 MiB and report to a breaker of their own (`<upstream>#dates`), so a throttled date API never opens the download breaker. A Maven HEAD answered 429 or 503 is no longer followed by the search API. New counter `nora_upstream_date_lookup_total{registry,outcome}` (`memo`, `fetch`, `breaker_open`). When no date is available the behaviour is unchanged (first-seen clock).
