**Release-date lookups: a 4xx is not an answer, galaxy listings date versions, cached copies are not re-held under `log`, pub refresh is memoised (Maestra fork, review R40–R43, #307)** — the gems, Maven and Terraform date lookups took any 4xx other than 401/403/429 (a 400, 408, 410, 451, a block page) as "the upstream does not know this name", which left a version undated instead of judging it by `unknown_date`; only a 404 is that answer now. An Ansible tarball is dated from every cached versions listing page again, including the `?limit=100` page `ansible-galaxy` asks for, which since #287 was cached under a key the date reader did not read. The write time of NORA's cached copy dates an undated Ansible, Go or Terraform (provider and module) version only under `unknown_date = "hold"` (where a copy held past `min_release_age` is served) or when a kept answer lacking the version was reused unasked; under the default `log` an undated version is served on a cache hit as it was on the miss that cached it, instead of being refused for `min_release_age` after the first download. The pub archive download's listing refresh goes through the release-date memo: a refresh that lists the version, dated or not, is not repeated for `pub_dart.metadata_ttl`, one that does not list it (or failed) at most once a minute, and a version such a kept refresh does not list is held as released now until the next one. Operators: an upstream whose listing rows carry no `published` is asked once per `metadata_ttl` per package instead of on every archive download; `nora_maven_date_lookup_total` counts a non-404 4xx of the search API as `status` instead of `missing`.
