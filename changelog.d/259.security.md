**An npm version newer than the cached release dates is dated by the upstream before the age check (audit A094)** — the tarball handler dated a version from the `dates.json` companion (or the cached packument) written at the last packument fetch, without checking that it listed the version asked. A version released after that fetch had no date, `min_release_age` skipped it, and with the digest quarantine only observing, its first download was served; the packument refetch that found the tarball came after the curation decision. With `server.trust_upstream_dates`, a cached map that dates other versions but not the requested one now falls through to the upstream packument fetch (single-flight, cached as before), so the first download is judged by the version's own date, as on a cold cache and on every later request. The fetch replaces the tarball step's own refetch, so upstream traffic stays the same; an upstream failure still ends in the tarball step's error. An upstream that sends no `time` map is not refetched.
