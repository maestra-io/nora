**Docker: `[curation.docker] quarantine_observe_fallback` answers a moved tag with its admitted copy under observe (Maestra fork, issues-maestra#1649, #309)** — under `quarantine = "observe"` a floating tag that moved to a digest the quarantine still holds answered with that held digest, so Renovate, which pins what a `HEAD` of the tag returns in `Docker-Content-Digest`, proposed digests the `base-images` check (`x-nora-quarantine: pending`) then failed for up to `quarantine_ttl` (50 red Renovate PRs on 19.11.2026 for `mcr/dotnet/sdk:10.0` and siblings). With the option on (default off; `NORA_CURATION_DOCKER_QUARANTINE_OBSERVE_FALLBACK`), such a tag answers as under `enforce`: 200 with the copy NORA admitted for it on `GET` and `HEAD`, plus `x-nora-quarantine-held` and `x-nora-quarantine-held-until`, counted `nora_docker_quarantine_tag_held_total{outcome="observe_fallback"}`. A brand-new tag (no admitted copy) and a request by digest are served as under observe, never a 403. The held digest is cached and its clock runs as before, so the tag moves on the first pull after it matures; `quarantine_exempt` repositories and break-glass exceptions are not held. Set in any other `[curation.<registry>]` section it is a configuration error.
