**PyPI and Terraform guard the file URLs their upstream's metadata names (Maestra fork, maestra-io/nora#274, audits A100, A104, A106)** — a PyPI file or `.metadata` named by an upstream index, and a Terraform provider or module archive named by the registry's metadata, were fetched on any host, a loopback or private IP literal included, and with `server.allow_private_upstreams` set also through a redirect or a name resolving to such an address; Terraform also sent `terraform.proxy_auth` to whatever host the metadata named. Such a fetch now answers 502 unless the new `pypi.allow_private_file_hosts` or `terraform.allow_private_hosts` (env `NORA_TF_ALLOW_PRIVATE_HOSTS`) is set, both default `false` — a private PyPI mirror or private Terraform upstream needs its switch — and the Terraform credential goes to the upstream's own origin only. Helm charts use the same shared check (`helm.allow_private_chart_hosts`) and, with private upstreams not allowed, the shared upstream client, so they now honour an outbound proxy. A Terraform provider file with no stored metadata is guessed from releases.hashicorp.com only in the `hashicorp` namespace (any other answers 404 instead of possibly another provider's file), the platform metadata is stored before the answer that names the archive, and the file path's namespace, type and version are validated (400).
