**PyPI and Terraform guard the file URLs their upstream's metadata names (Maestra fork, maestra-io/nora#279, audits A100, A104, A106)** — a PyPI file or `.metadata` named by an upstream index, and a Terraform provider or module archive named by the registry's metadata, were fetched on any host, a loopback or private IP literal included, and with `server.allow_private_upstreams` set also through a redirect or a name resolving to such an address; Terraform also sent `terraform.proxy_auth` to whatever host the metadata named. Such a fetch now answers 502 unless the new `pypi.allow_private_file_hosts` (env `NORA_PYPI_ALLOW_PRIVATE_FILE_HOSTS`) or `terraform.allow_private_hosts` (env `NORA_TF_ALLOW_PRIVATE_HOSTS`) is set, both default `false` — a private PyPI mirror or private Terraform upstream needs its switch — and the Terraform credential goes to the upstream's own origin only. Without its switch, such a file is fetched directly with the DNS-pinned client Helm charts already used (no outbound proxy, which would resolve the name itself), and a redirect from https to http is refused; Helm now goes through the same shared check (`helm.allow_private_chart_hosts`), and a registry's switch now also works when `server.allow_private_upstreams` is off. A Terraform provider file with no stored metadata is guessed from releases.hashicorp.com only in the `hashicorp` namespace (any other answers 404 instead of possibly another provider's file), the platform metadata is stored before the answer that names the archive (a failed write answers a retryable 503 outside `hashicorp`), and the file path's namespace, type and version are validated (400).
