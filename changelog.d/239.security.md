**OIDC role-rule wildcards stay inside one `sub` field; issuer and JWKS URLs must be https (Maestra fork, audit A022, B23)** — a `*` in a role-rule pattern matched any characters, `:` included, so `repo:org/*:ref:refs/heads/main` also matched a subject with extra fields that merely ended with `:ref:refs/heads/main`. A `*` that ends the pattern still matches the rest of the subject; every other `*` now matches within one `:`-separated field, and a subject that no longer matches a write rule falls through to the next rule (typically a trailing-`*` read rule). Startup now refuses an enabled OIDC provider whose `issuer` or `jwks_uri`, or an enabled `auth.teleport.jwks_url`, is not an `https://` URL (`http://` stays allowed on a loopback host), and a `jwks_uri` found by OIDC discovery that is not https is ignored in favour of `{issuer}/.well-known/jwks.json`.
