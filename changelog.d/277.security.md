**Hosted NuGet writes hold across processes (Maestra fork, audit A033)** — the hosted feed's state document is now updated by compare-and-swap on the store (ETag `If-Match` on S3/R2, generation on GCS, a hash check on local disk): when another process (the second pod of a rolling update, `nora import`, `nora nuget rebuild`) wrote it between the read and the write, the update is read and applied again, up to 8 times, then answered 503. Pushes, unlist/relist, the retention pass and `nora nuget rebuild` all go through it, so a version pushed through one server is no longer dropped by a write from the other. A package blob is created only when its key is free (a temp upload plus a create-only store-side copy), so two pushes of one version with different bytes store the first and answer the second 409; the same bytes still succeed. Before, the per-process publish lock was the only guard, the last writer's bytes replaced a published version, and a concurrent document write could drop an acknowledged version. Operators: a retry of a push that failed after its package was stored now gets 409 when it carries different bytes (same bytes: 201/200); heavy two-process contention on one ID can end in 503 instead of a silently lost version; a store without conditional writes is written as before and counted in the new `nora_storage_conditional_fallback_total` metric, which should stay 0 on R2.
