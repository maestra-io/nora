**RubyGems `.gem` and gemspec downloads served by one function (Maestra fork, maestra-io/nora#211)** — `download_gem` and `download_gemspec` carried the same cache, quarantine, namespace-isolation and upstream code twice, and the gemspec copy could fall through to the upstream for an internal name the isolation check let pass. Both now go through `serve_gem_file`: an internal name with no local copy is refused or 404 on both paths and never proxied. The allowlist integrity pin and ranged reads stay `.gem`-only (the pin names the `.gem`'s digest).
